# Архитектура

## Цели

SnippetDeck хранит библиотеку на устройстве и не требует собственного сервера или учётной записи. Google Drive подключается по желанию; резервная копия работает без него. Приоритеты — подстановка у курсора, явные изменения и восстановление через копии, совместимость данных установленного приложения и небольшой объём инфраструктуры.

## Границы системы

```text
Android: Compose → репозиторий → Room → индекс триггеров службы → поле ввода
Desktop: редактор Tauri → Rust-библиотека → локальный JSON → индекс агента → поле ввода
                            │
                            ├─ явный импорт/экспорт копий (совместимые JSON и текст)
                            ├─ необязательная синхронизация в Drive (файл на устройство)
                            └─ GitHub Releases → подтверждение → системный установщик
```

Приложения разделяют форматы, но не код выполнения: хранение и системные разрешения Android отличаются от desktop. Общий слой реализации связал бы решения, которые должны меняться независимо. На обеих платформах агент ввода читает локальные данные, без сетевых запросов на пути каждого нажатия.

| Каталог | Ответственность |
| --- | --- |
| `app/src/main/java/.../data`, `domain`, `service` | Хранение Room, правила триггеров и редактирование полей Android |
| `app/src/main/java/.../sync`, `update`, `util` | Обмен Drive, проверенные обновления и переносимые копии |
| `app/src/main/java/.../ui` | Редактор Compose и действия платформы |
| `desktop/src-tauri/src` | Rust-библиотека, агент ввода, Drive, обновления и команды Tauri |
| `desktop/ui` | Статический редактор без пакетного менеджера frontend |
| `.github/workflows` | Проверка Android, desktop-пакеты и согласованный выпуск |
| `docs`, `design` | Документация, публичный сайт и визуальные материалы |

## Подстановка

`TextExpansionService` получает события Android Accessibility и обновляет индекс триггеров при изменении списка включённых сниппетов. Поэтому пробел в другом приложении не запускает поиск по всей библиотеке. Служба находит триггер непосредственно перед курсором, заменяет только его диапазон, сохраняет суффикс поля и ставит курсор после замены. Если узел не сообщает выделение, допустима только подстановка в конце поля. Нажатие Backspace сразу после подстановки возвращает триггер там, где поле поддерживает редактирование. Виртуальный `!help` строится из включённых записей. Если служба запускается до разблокировки телефона, она ждёт доступа к зашифрованной библиотеке; первое событие после разблокировки включает наблюдение за ней.

Поиск триггера ограничен 40 кодовыми точками Unicode. Поля паролей, нередактируемые узлы и собственный редактор пропускаются; смена фокуса или окна сбрасывает историю отмены. Индекс триггеров и виртуальная справка строятся на фоновом диспетчере, затем заменяют состояние службы в главном потоке. Плейсхолдеры обрабатываются одним проходом с кэшем шаблонов даты на одну вставку. Служба никогда не отправляет поле ввода.

На компьютере Rust-агент хранит короткий буфер триггера и индекс, который обновляется только при изменении библиотеки. В Windows нативные обработчики клавиатуры отбрасывают только события с меткой SnippetDeck, продолжая учитывать реальный ввод и модификаторы. Символы определяются по раскладке активного окна без присоединения очередей ввода. Каждая замена отправляется одним пакетом `SendInput`; для вставки используется виртуальная клавиша V независимо от языка ввода. macOS и Linux X11 используют `rdev` и `enigo`; в X11 работает быстрый `libxdo`. В Wayland подстановка выключена.

Один рабочий поток последовательно выполняет вставки. Ожидающая замена отменяется, если новый ввод сделал диапазон триггера неактуальным; Windows также проверяет активное окно и нажатые модификаторы перед отправкой. Текст с переносами строк или табуляцией вставляется через буфер обмена, чтобы Enter не отправил поле, а Tab не сменил фокус. Windows также вставляет через буфер текст длиннее 256 байт UTF-8, ограничивая память и число событий нативного ввода. Повторные вставки сохраняют общий исходный снимок буфера и восстанавливают его после короткой паузы, если пользователь не скопировал другие данные. Восстановление буфера не задерживает следующие замены. Backspace на компьютере работает как обычная команда редактора: агент не может проверить вставленный текст и не должен удалять предполагаемую длину сниппета. Для отмены используется команда целевого редактора.

Агент не читает и не сохраняет содержимое всего поля. Клики мышью, навигация и сочетания клавиш очищают буфер триггера. Закрытие редактора освобождает WebView, а агент остаётся в трее.

## Данные и стоимость операций

`SnippetDao` хранит Android-данные в Room. Схема v2 сериализует псевдонимы как JSON в прежней таблице; миграция 1→2 заполняет старые строки пустыми списками, не теряя сниппеты. Основной триггер получает `!`, псевдонимы лишь обрезаются по краям. Все триггеры уникальны без учёта регистра. Полное восстановление сначала проверяет файл и затем заменяет данные одной транзакцией.

Сохранение проверяет уникальность и пределы резервной копии внутри транзакции. При редактировании и удалении строка сравнивается с версией, открытой пользователем: синхронизация или другая запись не могут быть молча перезаписаны. Desktop передаёт исходный сниппет в Rust для такого же сравнения. Импорт назначает новые локальные ID; синхронизация сохраняет ID оставшихся сниппетов и записывает только добавления, правки и удаления. Изменение другой записи не обесценивает открытый редактор. Системная копия Android включает базу Room с журналами и настройки оформления; метаданные синхронизации остаются в `noBackupFilesDir`, чтобы восстановленная установка получила собственную идентичность.

Компьютер хранит библиотеку отдельным JSON в каталоге данных приложения. Библиотека и метаданные синхронизации используют общий механизм: запись временного файла рядом, сброс на диск и переименование. В Unix файлы создаются приватными. Библиотека использует оболочку Android `format=snippetdeck-backup`, `schemaVersion=2`. Метаданные синхронизации хранятся отдельно. Нельзя заставлять два работающих экземпляра одновременно писать в один файл библиотеки.

Предел — 10 000 сниппетов и 2 МБ JSON-копии. Desktop сериализует всю библиотеку при сохранении; индекс ввода обновляется после изменения библиотеки. При открытии, сохранении или ручном запросе синхронизация получает список не более чем из 50 файлов устройств. Локальные метаданные помнят Drive `version` каждого файла: неизменённые копии уже представлены в объединённой реплике и не скачиваются повторно. При отсутствии версии файл читается всегда; явный выбор другой библиотеки также читает её заново. Изменённые файлы по-прежнему передаются целиком в заданных пределах; повышение лимитов потребует новых измерений сети и слияния.

Синхронизация читает по одному удалённому файлу и оставляет только различающиеся, не вытесненные версии. Одинаковые копии и старые ревизии отбрасываются при чтении; равные параллельные значения объединяются после полного обмена. Расход памяти определяется сохранившейся библиотекой и неразрешёнными версиями, а не полной копией каждого устройства. История удалений ограничена 20 000 ключами записей; слияние сверх предела завершается до замены локального состояния.

## Интерфейсы

Android Compose отвечает за редактирование, поиск, включение сниппетов, настройку специальных возможностей, темы, копии, Drive и ручную проверку обновлений. Импорт заранее показывает число записей и предупреждает о замене библиотеки. Темы Chalk, Ink и Parchment имеют фиксированные схемы Material 3 без цвета обоев. Android хранит значения `WHITE`, `BLACK`, `SEPIA`, desktop — `white`, `black`, `sepia`; старые Android-значения `LIGHT`/`DARK`/`SYSTEM` преобразуются в ближайшую тему. Список идёт под компактной верхней панелью и нижним поиском. Haze 2 захватывает список один раз для трёх стеклянных блоков, отрисовывает глубину, преломление у краёв и блики под чёткими элементами управления. Фоновый цвет материала скрывает исходные резкие пиксели. При уменьшенной прозрачности или системном высоком контрасте захват выключается и блоки становятся сплошными, независимо от режима энергосбережения. При открытии клавиатуры нижние блоки следуют за изменившейся высотой окна. Формы непрозрачны, плейсхолдеры раскрываются по запросу.

Android наблюдает одну библиотеку редактора и фильтрует её в памяти на фоновом диспетчере. Поиск понимает регистр Unicode и считает `%` и `_` обычными символами. Оба редактора ограничивают текст превью 160 символами, не передавая полную замену в разметку строки. Состоянием интерфейса управляют view model и репозитории; выбор файлов и буфер обмена остаются на границе UI.

Экран редактора держит черновик и исходную строку в небольшой view model: пересоздание Activity сохраняет введённый текст и версию, с которой сравнивается запись. Черновик остаётся в памяти, пока существует этот экран; в резервные копии он не входит и завершение процесса переживать не обязан.

На компьютере статический WebView показывает список и редактор рядом в широком окне и полный экран редактора в узком. Поиск и меню находятся на полупрозрачном уровне управления; при ограниченной прозрачности они становятся непрозрачными. Rust отвечает за хранение, проверку данных, файловые диалоги и подстановку; интерфейс не читает файлы и не обращается в сеть напрямую. На экране одновременно создаётся не более 80 строк библиотеки, пока пользователь не запросит остальные.

## Резервные копии

`SnippetBackupCodec` сериализует и проверяет формат отдельно от Android-хранилища. JSON имеет `format=snippetdeck-backup`, `schemaVersion=2`; компактный текст начинается с `SNIPPETDECK_BACKUP_V2` и содержит gzip в URL-safe Base64. Читаются также старые raw-array, v1.0 JSON и текст V1. Проверка отвергает слишком большие файлы, будущие схемы, пустые замены и конфликты триггеров. Пустая корректная копия очищает библиотеку только после подтверждения. На Android `ImportExportManager` работает с content URI; desktop поддерживает те же форматы без локальных идентификаторов строк.

## Необязательная синхронизация Drive

`SyncLibrary` на Android и `sync.rs` на компьютере реализуют `snippetdeck-sync` v1. Ключ записи — основной триггер без учёта регистра; его переименование означает удаление и создание. Запись содержит сниппет или маркер удаления и часы версий. Каждое устройство хранит базовую версию и пишет собственный файл в скрытой папке `appDataFolder`, не перезаписывая файл другого устройства. Независимые изменения объединяются, а разные значения одного триггера остаются конфликтом до явного выбора. Маркеры удаления не дают старой офлайн-копии воскресить удалённое. Android перед сохранением сверяет Room-строки в транзакции, desktop проверяет локальную библиотеку под блокировкой.

Ключи синхронизации сохраняют перевод основного триггера в нижний регистр. Совпадения триггеров и псевдонимов проходят через тот же выбор при конфликте. Результат проверяется в памяти без круговой сериализации JSON. Конфликтная библиотека хранится в локальных метаданных и не загружается как окончательная версия. **Use this device** объединяет увиденные часы версий и сохраняет локальную библиотеку; **Use other device** принимает разрешённую библиотеку единственного другого устройства. Отключение сохраняет локальные сниппеты и облачную историю. Сетевые запросы выполняются при открытии, локальном изменении или вручную, без фонового опроса.

Android запрашивает только `drive.appdata` через Google Play services. Desktop открывает браузер с PKCE и локальным callback; Google требует секрет нативного OAuth-клиента для обмена кодом. Этот секрет передаётся при сборке установщика и не является серверным секретом. Refresh token хранится в хранилище ОС, когда оно доступно, иначе только в памяти сеанса; он не входит в копии и не передаётся WebView. Google может читать данные в Drive: сквозного шифрования нет.

## Обновления приложения

Android `UpdateViewModel` управляет состоянием проверки и загрузки, `GitHubReleaseUpdater` читает `releases/latest` и проверяет APK, `UpdateInstaller` передаёт его системному установщику через `FileProvider`. При обычном запуске запрос делается один раз и только при подтверждённом соединении; из контекстного `PROCESS_TEXT` запроса нет. APK проверяется по имени, SHA-256, идентификатору пакета, версии, возрастающему versionCode и сертификату релизной подписи.

Desktop `update.rs` проверяет релиз один раз при старте и по команде редактора. Загрузка требует подтверждения, имя установщика выбирается по ОС и архитектуре, размер и SHA-256 сверяются с GitHub. Проверенный MSI, DMG или DEB открывает ОС; на Windows запущенное приложение закрывается перед заменой MSI. Ни одна платформа не опрашивает сеть периодически и не устанавливает обновления без пользователя. Запросы к GitHub не содержат сниппетов; текст из полей ввода не записывается и не передаётся.

## Границы безопасности и приватности

Запросы обновлений передают только запрос публичных метаданных GitHub, без библиотеки и наблюдаемого ввода. Подключение Drive передаёт пользовательские сниппеты и метаданные синхронизации, но не текст из других приложений. Подстановка через буфер обмена временно помещает в него текст сниппета; менеджеры буфера могут сохранить этот текст. Экспорты выполняются по запросу пользователя и содержат личные данные. Android также поддерживает системное резервное копирование библиотеки. Токены и материалы подписи не входят в исходники и переносимые копии.

## Совместимость

Сохраните Android application ID, namespace, имя базы Room, имена настроек и ключей, сертификат подписи, имена файлов GitHub Releases и читаемые форматы копий. Их изменение требует явной миграции и проверки обновления существующей установки. Исторические идентификаторы остаются технической совместимостью, а не нынешним названием продукта.
