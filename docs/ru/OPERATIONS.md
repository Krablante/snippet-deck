# Эксплуатация SnippetDeck

У SnippetDeck нет собственного сервера для развёртывания. Сопровождаются сайт GitHub Pages, Android и desktop CI и единый стабильный релиз с подписанным APK и четырьмя desktop-установщиками. Установка, использование, копии и пользовательские ошибки обновления описаны в [руководстве](GUIDE.md); здесь — сборка и выпуск.

## Сборка и CI

Android workflow запускает unit-тесты, lint и отладочную сборку. Desktop workflow собирает Linux x64 (`.deb`), Windows x64 (`.msi`), а также macOS Apple Silicon и Intel (`.dmg`) на runner’ах соответствующих ОС. Push и pull request только с документацией не запускают сборки приложений; изменения кода или workflow платформы запускают соответствующие задания. Ручной запуск desktop workflow сохраняет пакеты в Actions и не публикует релиз.

Инструменты и команды для локальной разработки находятся в [Разработке](CONTRIBUTING.md). Для Linux нужен `libxdo-dev`, а `.deb` устанавливает зависимость `libxdo3`. Текущие macOS-пакеты не подписаны и не нотарифицированы. Для установки без предупреждений Gatekeeper понадобится подпись и нотарификация с Apple Developer учётной записью сопровождающего.

## Выпуск из `main`

Используйте `.github/workflows/release.yml` с семантическим тегом, например `v1.8.3`. В релиз обязательно входят официальный подписанный APK и все четыре установщика. Оба приложения смотрят на GitHub `releases/latest`; релиз только для desktop сломал бы Android-обновления.

Перед запуском workflow:

1. Повысьте `versionName` и возрастающий `versionCode` в `app/build.gradle.kts`; ту же версию укажите в `desktop/src-tauri/Cargo.toml`, `Cargo.lock` и `desktop/src-tauri/tauri.conf.json`. Обновите ожидаемый Android versionCode в релизном workflow.
2. Сверьте тег с обеими версиями, пользовательские изменения с ENG/RU документацией и дождитесь нужных проверок CI.
3. Убедитесь в наличии зашифрованных учётных данных Actions. Никогда не помещайте keystore, параметры подписи, OAuth-токены или секрет desktop OAuth-клиента в Git.

Workflow проверяет тег и desktop OAuth-клиент, запускает Android-тесты/lint и подписанную сборку, сверяет идентификатор приложения, версию, возрастающий versionCode и закреплённый сертификат подписи. Затем собирает четыре desktop-пакета, собирает пять бинарников и `SHA256SUMS.txt`, сверяет все пять опубликованных GitHub digest с ведомостью и число файлов в черновике и публикует единый стабильный релиз. `preview=true` публикует предварительный выпуск; встроенные проверки продолжают видеть прежний стабильный релиз до его перевода в stable. При замене файла повторите проверку целостности.

После публикации откройте анонимный API `releases/latest`: пять файлов с правильными именами, ненулевыми размерами и `sha256:` digest, контрольную ведомость и стабильный тег. На доступных устройствах установите APK поверх прежней версии без удаления данных и проверьте триггер, псевдоним, отмену, `!help`, копию и передачу обновления установщику. На доступных компьютерах проверьте запуск установщика и сохранение локальной библиотеки. Отметьте платформы, которые не тестировали на устройстве: успешная сборка CI не доказывает работу во всех целевых редакторах.

## Подпись и Google Drive

Для обновления установленного Android-приложения нужны тот же application ID и сертификат. Локальная подписанная сборка принимает игнорируемый `keystore.properties` (шаблон `keystore.properties.template`) либо `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. Другой ключ несовместим с установленной версией. Релизный workflow получает официальный ключ из зашифрованных секретов Actions и проверяет закреплённый сертификат. Ключи и пароли не должны попадать в репозиторий или логи.

Публичное приложение использует разные OAuth-клиенты Android и desktop с правом `drive.appdata`. Зарегистрируйте Android release-пакет и сертификат у Google; отладочному пакету и подписи нужен отдельный клиент. Desktop-обмен токена требует `SNIPPETDECK_DESKTOP_OAUTH_CLIENT_SECRET` при сборке. Релизный workflow отвергает отсутствующее или неверное значение. Его можно извлечь из нативного установщика, поэтому это не серверная аутентификация. Refresh token пользователя хранится в хранилище ОС или памяти сеанса и не входит в пакеты.

Для брендинга Google OAuth используются [публичный сайт](https://krablante.github.io/snippet-deck/) и [английская политика](https://krablante.github.io/snippet-deck/privacy.html). GitHub Pages публикует `docs/` из `main`: английская страница отражает [PRIVACY.md](../../PRIVACY.md), русская `docs/ru/privacy.html` — [русскую политику](PRIVACY.md). Проверяйте реальный статус экрана согласия и вход через аккаунт перед заявлением о публичном доступе к Drive. У External OAuth в режиме **Testing** разрешения истекают через семь дней. Общий домен Pages не подходит для возможной будущей проверки владения DNS; понадобится собственный домен сопровождающего.

## Восстановление и upstream

Экспорт содержит всю локальную библиотеку. Перед переустановкой или разрешением конфликта сохраните копии со всех затронутых устройств. Импорт целиком заменяет локальные данные после подтверждения; отключение Drive не удаляет облачные файлы. Пользовательский путь описан в [руководстве](GUIDE.md#резервная-копия-и-перенос). Не направляйте два работающих desktop-экземпляра в один файл библиотеки.

Изменения [Expander](https://github.com/rrajath/expander) просматривайте отдельно. При переносе сохраняйте логику курсора, миграции данных, подпись, форматы копий и указание авторов.
